# Временная диагностика погодных Web Push (Cloudflare)

Эта диагностика добавлена в `cloudflare/src/worker.js` без изменения логики отправки.
Пока Worker не развёрнут в Cloudflare, запись в GitHub **не включает** новые логи.

## Включение
1. В Cloudflare Workers & Pages → `autojournal-sync` → **Edit code** сохраните резервную копию опубликованного `worker.js` (особенно если вносили правки прямо в Cloudflare).
2. Сравните текущий опубликованный файл с [исходником GitHub](https://github.com/vzloman546-design/autojournal-pwa/blob/main/cloudflare/src/worker.js). Убедитесь, что при замене не потеряются другие, более свежие изменения.
3. Замените содержимое `worker.js` актуальным исходником из GitHub и нажмите **Deploy**.
4. В Observability → Logs найдите события с префиксом `[weather-push]` после следующего запуска Cron. Расписание в настоящее время `0 */6 * * *` — 00:00, 06:00, 12:00, 18:00 **UTC**.

## События диагностики

- `run_start` — количество включённых подписок, обнаруженных Worker.
- `forecast_result` — число дней прогноза и был ли достигнут температурный порог (`thresholdMet`).
- `push_response` — HTTP-код ответа push-сервиса (например, 201 или 403), **не** подтверждение показа уведомления на экране.
- `push_accepted` — сервер обновил D1 после успешного HTTP-ответа.
- `push_skipped` — отправка пропущена по причине `already_active` или `cooldown`.
- `subscription_error` — безопасный код ошибки и стадия (`forecast`, `apple_push`, `database_...`).
- `run_summary` — итог по всем подпискам.
- `setup_error` — ошибка подготовки схемы D1 или чтения списка подписок.

Диагностика не выводит координаты, точные адреса и endpoint-URL, токены, VAPID-ключи,
идентификаторы подписок или исходные сообщения исключений. Поле `slot` — временный
порядковый номер подписки внутри одного запуска, не стабильный идентификатор устройства.

Если `thresholdMet=false`, фоновый прогноз не нашёл похолодание.
Если `thresholdMet=true`, а затем `subscription_error`, ошибка локализована указанной стадией.
Если `push_accepted` есть, но уведомления на iPhone нет, надо исследовать доставку/Service Worker.

## После диагностики
Удалите временное логирование после установления причины; не сохраняйте расширенные
журналы бессрочно. Не изменяйте содержимое D1 и не публикуйте endpoint-URL или ключи.
